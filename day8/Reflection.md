# Day 8 Reflection

## 1. What was the hardest concept to understand?

The hardest concept was understanding how the frontend, API, and database work together in a high-traffic ticketing system. I learned that displaying an available seat is not enough. The database must confirm that the seat is still available when a customer attempts to reserve it. Database transactions and constraints help prevent two customers from booking the same seat.

## 2. How did I work through the challenge?

I broke the design into smaller sections, including requirements, traffic estimates, API endpoints, database tables, and system architecture. Writing each section separately helped me understand how the components connect. I also considered what could happen when many customers try to purchase tickets at the same time.

## 3. What would I improve in my capstone project?

I would improve the user experience by making the interface clearer and providing useful feedback when an action succeeds or fails. I would also expand testing to cover invalid inputs, network errors, and situations where multiple users attempt the same action. These improvements would make the application easier to use and more reliable.

## 4. What do I want to learn next?

I want to learn more about backend development, database transactions, API integration, automated testing, deployment, and application security. I would also like to practise load testing so I can identify performance problems before an application is used by many people.
